# Memory policy

## CLAUDE.md
Keep only durable every-session rules and hard-to-infer project facts.

## Auto-memory
Good:
- stable project quirks
- corrections
- recurring build/test facts

Bad:
- temporary task state
- speculative conclusions
- obsolete bugs
- copied documentation

## Obsidian
Use for durable cross-project engineering knowledge, research and architecture decisions.

Retrieve targeted notes instead of loading the whole vault.

## Compression
Before compressing memory:
1. create a backup
2. inspect the compressed result
3. ensure commands, paths, constraints and decisions remain exact
4. compare before/after
